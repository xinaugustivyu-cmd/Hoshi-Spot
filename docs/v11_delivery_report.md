# Hoshi Spot V1.1 离线开发交付报告

日期：2026-10-27。分支：`hoshi-v1.1-experiment`，基线提交 `e172f2a8e3f5c3e092ac34aebd563469de5a3c85`。本轮只编写候选系统、离线测试和历史回放；**没有启动 A/B/C 实时 Dry Run，没有连接交易账户或执行真实买卖**。

## 已实现

1. 冻结 V1：23 个原件及归档逐一校验 SHA-256，一致 23/23。原始策略、配置、历史行情、回测 ZIP 和报告均未改写。见 `v11_baseline_audit.md`、`../baselines/v1_20261027/MANIFEST.sha256`。
2. 统一持久风控：A/B/C 同一代码和参数哈希 `4237398a56508e9c67d2b4a6127a045a8dc2bd2515952be8c496afbce7febe0a`。每组独立 SQLite，记录模拟交易、周初权益、逐时权益、风险事件、人工恢复及阶段。规则包括 16 USDT/20%/1% 单笔上限、最多一仓、止损后至少 24 小时冷却、UTC 周亏损 3% 短暂停、滚动 14 日净亏 5% 和权益高水位回撤 5% 人工停机、数据故障两根新收盘 K 线恢复以及紧急停机。已有模拟仓位的原始退出继续允许。见 `v11_risk_architecture.md`。
3. A 继承 V1 原始信号；B 仅把 EMA/RSI 趋势失效退出改为连续两根已收盘 1h K 线；C 仅增加已收盘 4h EMA20 高于三根前 EMA20 的入场筛选。三者没有调整止盈、止损、交易对或风险门槛。
4. 共用历史行情事件 ID、UTC 时间与收盘 K 线校验；逐笔模拟记录导出、独立审批记录库及中文三组周报工具。历史 ZIP 没有真实信号生成/订单提交时刻，导出字段留空，不伪造。审批状态 APPROVED 只改变研究记录，没有下单接口。
5. 三份隔离的 Docker Compose 候选配置：各自钱包、交易库、风险库、日志和本机 WebUI 端口。入口检查拒绝非 Dry Run、非现货、交易所密钥及不允许的环境覆盖。候选策略当前还会因实时共享行情源未验收而主动拒绝 Dry Run 启动。

## 已测试及原始证据

- Docker 内完整自动化测试：**64 项通过、0 项失败**，涵盖资金、风险边界、回撤、跨重启、人工恢复、数据异常、B/C 信号、4h 收盘对齐、配置拒绝和已有仓位退出。A/B/C 的 2024-01 离线短区间回测均可完成；A 的 7 笔与冻结 V1 同区间 7 笔逐笔净额一致，B/C 仅作执行路径冒烟测试，不据收益判断优劣。
- 2024-01-01 至 2026-10-01 的 A 组完整离线回放已完成。原始 ZIP 与独立风险账本的 **47 笔、-0.959835 USDT** 对账一致。原始 V1 为 **48 笔、-1.219886 USDT**，共同入场 47 笔；差异来自风控在一笔交易前提前停机，不能把净额差异称为风控改善收益。原始 V1 最后平仓为 2024-07-23 16:00 UTC，A 组为 2024-07-23 14:00 UTC。
- A 组在 **2024-07-23 14:00 UTC** 因 1h 收盘采样的权益高水位回撤触发 `HALTED_MANUAL_REVIEW`，持续至回测结束约 **799.417 天**。账本最大采样回撤 **5.232%**，Freqtrade 按已平仓交易报告的最大回撤 **4.784%**；两者计算口径不同。滚动 14 日规则在该路径上没有先于回撤触发。止损冷却曾于 2024-05-23 21:00 UTC 进入，2024-05-24 20:00 UTC 重新变为 ACTIVE（按前一小时平仓时间满足至少 24 小时）。
- 风险库有 24,143 条权益采样、144 个 UTC 周初快照和 47 条平仓账目。原生保护会在策略仓位回调前跳过信号，回调记录的被锁候选为 0，只是下界；独立重建指标层信号后，从最后一笔 A 组持仓结束至区间末有 **240 个**长期停机覆盖的候选（BTC 130、ETH 110）。原始 V1 48 笔、A 47 笔实际入场都能在同一重建集合中找到。这 240 个是指标条件满足的小时事件，不代表全部可以成交。
- 完整比较见 `v11_A_oos_comparison.md`，候选逐项见 `v11_A_blocked_indicator_candidates.csv`，逐笔导出示例见 `v11_trade_records_sample.csv`，三组周报样例见 `v11_weekly_example_20240101.md`。A 组长区间原始 ZIP 与 SQLite 只读副本及 SHA-256 清单位于 `../artifacts/v11_offline/`。

长区间回放在最后一次“缺失 K 线持久暂停”修补前启动；修补后的 64 项自动化测试通过，**尚未使用修补后的代码重跑完整长区间**。这项差异已在原始证据说明中保留，不能把该 ZIP 说成最终版本的全区间性能验证。

## 安全门禁与已知问题

| 门禁 | 状态 | 证据或后续工作 |
|---|---|---|
| 非 Dry Run、合约、杠杆、超额仓位拒绝 | 已测试通过 | 启动器、策略开仓闸门和风险模块的离线测试 |
| 风险状态缺失/损坏及钱包不一致拒绝新开仓 | 已测试通过 | 持久紧急停机及数据暂停测试 |
| 停机期间已有模拟仓位仍按原策略退出 | 已测试通过 | A/B 回调测试与长区间回放 |
| 三账户风险/交易库隔离及统一参数 | 配置与离线账本已测试 | 三组历史短区间单独运行，参数哈希一致 |
| 实时共用同一公开行情事件并记录接收时刻 | **尚未实现** | 只有历史共用文件回放层；不能启动三组实时 Dry Run |
| 镜像中不存在真实下单代码路径 | **未满足** | 固定的官方 Freqtrade 2026.9 镜像仍含通用实盘代码；启动器和策略拒绝实盘不能替代镜像级证明 |
| 实时容器重启、故障恢复、真实报价采样 | **未测试** | 本轮禁止启动长期运行容器 |
| B/C 长区间或滚动样本外绩效 | **未运行** | 仅短区间功能冒烟，不作投资结论 |

因此，**本版本不能启动实时模拟服务，也不能宣称满足“镜像中无真实下单路径”**。V1.1 的 Compose 仅供审查；即使以后人工批准运行，也必须先完成上述高优先级门禁。历史 1h OHLCV 不含 K 线内价格顺序、盘口与真实滑点，5% 回撤线只控制后续新开仓，不保证最大实际损失。2024–2026 区间已经用于诊断，不再作为 B/C 的独立样本外测试。

## 离线复现

在 `G:\Miracle\exchange` 使用本地 Docker Desktop；以下命令不会启动长期服务。每次回放须更换未使用过的 `HOSHI_V11_RUN_ID`，禁止复用或覆盖风控账本。

```powershell
docker compose run --rm --no-deps --volume .\tests:/freqtrade/tests:ro --volume .\docker-compose.yml:/freqtrade/docker-compose.yml:ro --volume .\docker-compose.v11.yml:/freqtrade/docker-compose.v11.yml:ro -e PYTHONPATH=/freqtrade/user_data --entrypoint python hoshi-dry-run -m unittest discover -s /freqtrade/tests -q
docker compose run --rm --no-deps -e HOSHI_V11_RUN_ID=A-oos-NEWID hoshi-dry-run backtesting --config /freqtrade/user_data/config.json --strategy HoshiSpotV11A --strategy-path /freqtrade/user_data/strategies --timeframe 1h --timerange 20240101-20261001 --fee 0.001 --dry-run-wallet 80 --enable-protections --cache none --export trades
```

回放结果的候选信号审计、逐笔导出和周报命令见对应 `tools/` 脚本的 `--help`；Windows 配置检查见 `v11_windows_docker.md`。不应对 B/C 在已查看的区间反复调参；后续需按时间顺序预登记滚动验证，再由用户决定是否进入安全的实时模拟验收。
