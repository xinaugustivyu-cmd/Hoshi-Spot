# Hoshi Spot V1.1 统一风控架构

状态：独立风控核心、A/B/C 离线策略、人工审批记录库、交易导出和周报工具已实现。实时共享行情源及镜像级无真实下单代码验证尚未完成；任何 V1.1 Dry Run 当前都被适配层主动拒绝启动。此文不构成实盘许可。

## 组件

- `user_data/hoshi_v11/risk/models.py`：固定风控参数、输入输出与参数哈希。参数不能放宽 16 USDT、20% 仓位、1% 单笔预算、4% 止损、周 3%、14 日 5%、回撤 5% 和最多一仓。
- `equity.py`：模拟权益 = 现金 + 开仓数量×公开价格×(1−预估平仓手续费)。现金已反映入场费用；不重复扣费。仓位预算取现金、16 USDT、20% 权益和 1% 计划损失限额中的最小值。
- `state_store.py`：账户独立 SQLite。保存阶段、全部平仓、UTC 周初权益、权益采样、状态事件和人工审批。缺失、损坏、账户或参数哈希不一致均拒绝新开仓，不会自动重建。
- `engine.py`：统一 A/B/C 状态机；每次采样把传入的完整模拟交易历史与数据库对账。历史交易缺失、同 ID 的结果改变、模拟现金与初始 80 USDT + 已实现损益 − 未平仓入场成本不一致，进入持久紧急停机。所有风险状态均允许原有模拟仓位继续按策略退出。
- `market_events.py`：历史 BTC/ETH 1h/4h 共享事件层，按决策时间截取已收盘 K 线，生成内容哈希事件 ID；历史数据没有真实网络接收时刻，明确记为未知。
- `freqtrade_strategy.py`：A/B/C 共用的离线 Freqtrade 适配；A 完整继承冻结的 V1 信号，B 只改变趋势失效出场，C 只增加 4h 入场筛选。重写仓位/入场闸门并保留短期 StoplossGuard。V1 原本的 100000 根 MaxDrawdown 不改动；新组由持久化风控模块决定长期停机。
- `approvals.py`：研究建议的独立审批记录库。APPROVED 只变更记录状态，没有订单执行入口。
- `tools/v11_export_trades.py`、`tools/v11_weekly_report.py`：从不可覆盖的离线回测 ZIP 和风险账本导出逐笔记录与中文周报。

## 状态与优先级

`EMERGENCY_HALT` ＞ `HALTED_MANUAL_REVIEW` ＞ `WEEKLY_PAUSE` ＞ `DATA_PAUSE` ＞ `COOLDOWN` ＞ `ACTIVE`。每次状态转换写入 UUID 状态 ID、账户、UTC 触发时间、规则、触发数据、参数哈希；每根有效 K 线记录权益、阶段峰值与回撤。新入场只在 `ACTIVE` 允许，退出在全部状态允许。止损冷却至平仓后 24h 与下一 UTC 日开始两者较晚时刻；周暂停至下周一 UTC 00:00。数据暂停需要两根**新**的健康已收盘 1h K 线。长期/紧急停机不因到期或重启自动解除。

14 日窗口精确定义为 `(now−14×24h, now]`。人工恢复会再次检查这个窗口；若仍达到阶段初始权益的 −5%，审批被拒绝且原停机保留。经批准的恢复创建新阶段局部峰值，但保留跨阶段交易、累计净损益、旧峰值、旧回撤和所有事件。实验账户各有独立账本，同一 `RiskPolicy.hash` 代表规则一致，交易路径及触发时间可不同。

## 估值与回测限制

历史研究只用离散 1h 已收盘行情估值，无法知道 K 线内真实峰谷、订单簿和滑点。Dry Run 的报价采样未来可以补充，但必须与 1h 收盘口径分别报告。Freqtrade 的原生回测最大回撤与本模块的“包含未平仓估值的高水位回撤”不能混用。5% 是拒绝新增风险的触发线，不是损失保证。

## 安全边界

候选启动器只接受 Binance 现货、无交易所密钥、80 USDT、`dry_run=true` 的 A/B/C 本地配置，清除未批准的 Freqtrade 环境覆盖项。策略启动再次检查；仓位回调与最后入场回调独立拒绝不安全请求。当前实时共享行情事件源尚未实现，因此 V1.1 Dry Run 启动会失败关闭。官方 Freqtrade 镜像仍包含其通用实盘代码，尚不满足“镜像中不存在真实下单路径”的更严格要求。所有测试仅为离线 Python 与 Freqtrade 回测，没有长期运行的模拟容器。
