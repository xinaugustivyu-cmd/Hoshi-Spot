## 3. 已认可方向的风控设计与实施条件

保持 80 USDT 可配置初始模拟本金、单笔最多账户资金 20%、计划 4% 止损、1% 单笔风险预算、最多一仓、现货无杠杆、`dry_run=true`。新增持久化、可审计的全局风险状态；所有风险判定在每次模拟新开仓前再次检查。多条规则同时触发时取最严格状态，短暂停止的到期不能清除长期停机。

| 规则 | 提议的精确定义 | 状态与解除 |
|---|---|---|
| 单次止损冷却 | 已平仓止损后拒绝新开仓；沿用当前至少 24 根 1h K 线的全局 StoplossGuard，并检查 UTC 当日止损。 | **短期暂停**；24h 与下一 UTC 日 00:00 两者较晚者以后自动复核，数据正常且无更严状态才恢复。 |
| 周亏损 3% | UTC 周一 00:00 起的已平仓净损益（扣除实际计入的手续费；只有被明确建模的滑点才可计入）达到该周起始模拟权益的 -3%；周初权益快照持久化，重启不能重置。 | **短期暂停**至下一 UTC 周一 00:00；到期后重新校验数据及更严状态。 |
| 滚动 14 日累计亏损 5% | 每次判定取 `(当前 UTC 时刻 − 14×24h, 当前时刻]` 内全部已平仓模拟交易的净损益；亏损达到阶段初始模拟本金的 5% 即触发。80 USDT 阶段阈值为 -4 USDT。窗口连续滚动，不能在自然周/月边界清零。阶段本金变更只能经人工启动新阶段并记录。 | **长期停机，需人工确认**；窗口随时间回升不会自动解除既有停机。人工确认前不生成新开仓建议。 |
| 最大回撤 5% | 以本阶段模拟账户权益高水位为峰值，按已实现与未实现损益计算 `(峰值−当前权益)/峰值`，达到 5% 触发；记录峰值、当前权益、交易与行情时间。 | **长期停机，需人工确认**；不再用 100,000 根 K 线代表人工审批。由于 K 线、成交和跳空，5% 是触发线，不保证实际回撤不会越过。 |
| 数据故障暂停 | 公开行情或指标数据缺失、过期、异常，或短暂 API 失败。 | **短期拒绝新建议与新开仓**；连续两个新收盘 1h K 线均通过时效、完整性及时间顺序检查，并且无更严锁时，才可自动复核恢复。 |
| 紧急停机 | 风险状态损坏、余额或模拟订单状态无法核对、反复数据故障、非 Dry Run 权限或任何安全约束失败。 | **长期停机，必须人工确认**；即使故障消失也不能自动恢复，不触发真实订单。 |

状态优先级：`紧急停机/人工确认` → `14 日或最大回撤人工停机` → `周暂停` → `日/止损冷却或数据故障暂停` → `允许评估入场`。事件窗口暂停仍可独立拦截。人工恢复仅允许在复核损益、权益、数据完整性及触发原因后为**模拟模式**创建新阶段；需留存批准人、时间、原因和新阶段基准，不得清除历史记录或自动切换实盘。

实施方式需在批准后细化：不能简单将 Freqtrade 的 MaxDrawdown 锁缩短后视为风险消失。应以独立的持久化硬停机闸门执行 14 日与最大回撤规则，Freqtrade 原生短期保护用于止损冷却；回测、Dry Run 使用相同状态规则和时区/权益定义。Freqtrade 原生 MaxDrawdown 仅基于窗口内**已平仓交易**计算，不能单独满足拟议的未实现损益高水位检查；回测与运行时两种实现之间必须逐时对账，并注明 1h OHLCV 无法重建 K 线内真实权益路径。保留 V1 基准不变，用单独版本进行实现与比较。

### 3.1 已有仓位如何处理

所有周、14 日、最大回撤、数据故障及紧急停机规则都**立即拒绝新开仓和加仓**，并记录触发瞬间每笔未平仓模拟持仓、名义金额和浮动损益。它们本身不发送强制平仓指令，也不延后已有仓位的风险减仓。现有仓位继续由 V1 的 **-4% 止损、+6% ROI、已收盘 1h EMA/RSI 趋势失效退出、14 日最长持仓**按原优先级处理；停机状态不能拦截这些退出回调。若重大事件或数据故障发生，仍允许 Freqtrade 正常管理已有仓位的模拟退出；行情不可用时不伪造价格或声称能保证退出成交，持续拒绝新建议，并保留故障审计记录。人工确认只针对**恢复新的模拟开仓**，不能放松既有持仓的退出规则。停机时未平仓浮亏可能继续扩大，因此 5% 是停止新增风险的触发线，不是账户损失硬保证。

### 3.2 实时估值与历史回测的精度

统一的核算定义为：模拟现金余额 + 未平仓现货按可用公开价格估值的市值 − 估计平仓手续费；已平仓净损益直接采用扣费后的交易结果，避免重复扣费。每阶段起点权益、权益峰值、每次采样价格/时间/来源、已实现和未实现分量必须留痕。共同的**可比较判定点**为每根已收盘 1h K 线；Dry Run 还可以在两次收盘之间用有效的公开报价做额外保守检查，若先触及 5% 就提前进入同一个人工停机状态。实时数据缺失或过期时拒绝新开仓，不以旧报价续算可交易权益。

历史 1h 回测只能在离散 K 线与 Freqtrade 撮合假设下估值：K 线高低点的先后顺序、盘口深度、盘中权益峰谷、跳空止损与真实滑点不可恢复。即使以收盘价重建浮动权益，真实 Dry Run 的盘中 5% 触发也可能早于回测，或回测因离散采样漏掉短暂越线。报告必须分别列出“1h 收盘采样回撤”和“Dry Run 报价采样回撤”，不得声称二者完全等价；若要缩小偏差，应在相同固定规则下另做更细周期数据回放，仍注明其 OHLCV 限制。Freqtrade 原始报告的成交后回撤数值也不得冒充这个新定义的浮动权益高水位回撤。

### 3.3 跨阶段风险记录与 V1 冻结基线

任何长期停机后恢复都必须生成新的阶段编号、审批记录和新阶段起点快照；**已平仓交易、旧阶段初始权益、累计净损益、历史权益峰值/最大回撤和停机记录永久保留**，不得因时间窗口到期、重启、改策略组别或新阶段而删除。滚动 14 日计算继续按真实 UTC 时间读取跨阶段交易，不在新阶段边界清空窗口；**人工确认也不能在该 14 日窗口仍超过 5% 时恢复新开仓**。最大回撤人工恢复可明确设定新阶段的局部权益峰值，但旧峰值和跨阶段累计回撤必须继续报告，禁止静默重置。5% 的分母按被批准的新阶段初始模拟本金固定；人工恢复记录必须明确承认累计风险。没有另行批准的跨阶段累计损失阈值时，不臆造数值自动限制，但也不得把新阶段报告说成此前损失已消失。持久化记录缺失、损坏或与模拟成交数据库不一致时进入人工紧急停机。

冻结副本已保存在 `baselines/v1_20261027/`：包括 V1 策略及依赖、配置、Compose、原始报告、BTC/ETH/SOL 1h/4h 数据和六份原始回测 ZIP，共 23 个文件。`MANIFEST.sha256` 为每个副本保存 SHA-256；已逐一与当前原件核对，一致数 **23/23**。该目录仅用于基线复现和差异核对，不作为新策略的可写数据目录。后续候选版本、实验输出和风险状态写到独立路径，不能覆盖这些文件。

### 3.4 A/B/C 三组使用同一风控

未来 A、B、C 各组必须导入**同一个版本的风控模块**，使用同一份只读风险策略参数、相同初始模拟本金/费用/时区/估值和恢复规则；运行记录附模块版本与参数哈希。各组使用各自独立的模拟账户与审计账本，避免组间交易互相污染，但不可采用不同风控门槛。组间只允许其预先登记的交易信号或退出假设不同，不能分别放宽 14 日、周、最大回撤、止损冷却或安全闸门。每组要分别记录被风险锁阻止的候选信号、锁定时长及交易路径，比较时说明风控阈值相同但触发时点可因交易结果不同。**本补充不启动任何 A/B/C 模拟交易**；此前未获批准的 B、C 继续不运行。

### 主要风险与验收条件

1. **误恢复风险**：仅改 `stop_duration_candles` 会让 5% 回撤后的新开仓自动恢复，违背长期停机要求。验收：状态跨重启持久，短暂停止到期不会清除人工锁。
2. **规则口径风险**：14 日滚动、UTC 周与高水位使用不同分母/窗口；费用、未实现盈亏和阶段重置可能算错。验收：边界时刻、重叠触发、手工恢复、浮亏越线的自动化测试及逐时回放对账。
3. **执行风险**：5% 熔断或最大回撤只能及时停止新的模拟入场，不能消除现有仓位的跳空/滑点损失，也不能把 OHLCV 回测视为真实成交保证。验收：报告记录触发前后实际峰谷和最大越线幅度。
4. **数据风险**：无法确认权益/历史交易完整时一律拒绝新建议；不得通过重启、清空数据库或时间窗口到期绕过人工锁。验收：断电重启、数据缺失和异常行情场景。
5. **研究风险**：2024–2026 数据已用于此次诊断和对照，不再称为未触碰的独立样本外。验收：批准后用时间顺序/滚动样本外和实时 Dry Run 观察；不以移除风控或回测收益变正作为成功标准。
